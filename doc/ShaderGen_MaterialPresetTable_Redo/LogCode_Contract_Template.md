# LogCode 合同模板（Phase 通用）

## 1. 目的

用于统一各阶段日志命名、最小埋点与验收口径，避免实现/测试/回归阶段出现口径漂移。

适用范围：Phase1~Phase5（Phase0R/Phase3 已先行对齐，可按本模板继续收敛）。

---

## 2. 前缀字典

1. `VT-OK-*`
   - 策略组合合法且资源满足的命中路径。
   - 典型来源：组合真值表正向行（如 `VT-001`）。

2. `VT-ERR-*`
   - 策略组合非法，或组合合法但资源不满足。
   - 典型来源：真值表负向行、资源缺失场景（如 camera/viewport 缺失）。

3. `MT-MATCH-*`
   - Matcher 候选筛选、require 检查、质量降级轨迹。

4. `MT-FALLBACK-*`
   - fallback 触发、fallback 类型、最终采用结果。

---

## 3. 函数级最小埋点清单

1. recipe 组装函数
   - 输出策略轴最终值和来源（默认/映射/显式）。
   - 至少输出 1 条 `VT-*`。

2. 组合校验函数
   - 输出真值表 ID、判定结果、冲突或缺失键名。
   - 非法组合必须输出 `VT-ERR-*`。

3. 路由入口函数（如 RecipeToKey / Resolve 入口）
   - 输出策略到分支映射结果。
   - 分支失败必须输出 `VT-ERR-*` 或 `MT-MATCH-*`。

4. 候选评估函数（Matcher）
   - 输出候选枚举、失败原因、降级轨迹。
   - 命中输出 `MT-MATCH-*`；退化输出 `MT-FALLBACK-*`。

5. 最终创建链路函数（ProgramManager/MaterialLibrary）
   - 输出最终路径来源（命中候选、fallback、兼容旧路）。
   - 禁止静默替换。

---

## 4. 必填字段（失败日志）

失败日志必须同时包含：

1. preset
2. phase
3. quality
4. candidate_id（或等价候选标识）
5. missing_capability_keys（一个或多个）

---

## 5. 编码规则

1. 单次决策链至少产出 1 条阶段级 `VT-*` 或 `MT-*`。
2. `VT-*` 与真值表语义一一对应，不允许跨语义复用同一编号。
3. 进入 Matcher 主路由后，`MT-MATCH-*` 与 `MT-FALLBACK-*` 为强制输出。
4. fallback 日志必须可反推出触发条件与最终去向。

---

## 6. 阶段文档接入方式（模板）

在阶段文档中追加以下条目：

1. 在“核心契约”增加 `LogCode 契约` 小节，引用本模板。
2. 在“执行步骤”增加“函数级埋点最小清单”（可复制第 3 节）。
3. 在“验收标准”增加“前缀合规 + 语义对应”门禁：
   - 前缀覆盖：`VT-*` / `MT-*`
   - 语义一致：`VT-*` 对齐真值表

---

## 7. 验收检查单（Reviewer 用）

1. 是否存在静默 fallback？
2. 是否每条失败路径都有缺失能力键名？
3. 是否可从日志完整重建决策链？
4. 是否存在 `VT-*` 编号复用但语义不同？
5. 是否在 Matcher 路径缺失 `MT-MATCH-*` 或 `MT-FALLBACK-*`？

满足以上 5 项方可判定日志合同通过。
