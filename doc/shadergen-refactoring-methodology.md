# ShaderGen 数据驱动化与复杂度削减方法论

> 2026-08-30 定稿。从 ShaderGen 整套改造（T1-T3/候选/C1-C4/命名清理）提炼的
> 可复用重构方法论。适用：任何「演进叠加 + 样板膨胀 + 隐式协议」的自研代码。

## 一、总纲：先分类复杂度来源，再动手

改造前先回答：复杂度从哪来？三类来源对应三类处置：

| 来源 | 特征 | 处置 |
|---|---|---|
| 历史演进叠加 | 改名残留、僵尸宏、平行结构、废弃层 | 清理/删除 |
| 样板重复 | N 处相似实现（解析链、错误名函数、包装结构） | 收敛（同源/模板/表） |
| 隐式协议 | 顺序、结构、约定藏在代码里（拼接顺序、特判散落） | 显式化（列表/辅助函数） |

诊断工具：grep 全仓使用面、git 历史对照（分清「旧名」与「无用」）、行数统计量化。

## 二、核心原则（按优先级）

1. **单一真源**：同一信息只定义一处，其余位置引用/查询。平行表、双份实现都是债。
2. **零兼容层**：必用路径不留标志/分支。强制即删除——不保留历史 fallback（删宏删分支
   不留「假装可选」的兼容宏）。
3. **死代码零调用者即删**：先 grep 确认零调用者，再整段删除；删完全仓复查零残留。
4. **显式优于隐式**：顺序、协议、特判都要有名字、有位置、有表。注释辩解「顺序在串里
   可见」= 隐式协议信号。
5. **行为不变原则**：纯重构必须逐字节等价——hash、GLSL 输出、缓存 key 全不变。
   改了结构就要先确认 hash 输入序列逐字段一致。

## 三、判断模式（症状 → 手法）

| 症状 | 判断 | 手法（实例） |
|---|---|---|
| 同一枚举在多处维护名字表（解析 if-else ×2） | 双真源 → 合并 | T1 语义注册表（GetXxxName/ParseXxx/Count 三件套） |
| 枚举 + 名字 switch 成对出现 ×N | 样板 → 同源生成 | C2 X-macro（`#define HGL_ERROR(name) ...` 列表单源） |
| 结构 A→B→A 往返转换，无信息增益 | 冗余层 → 删 | C1 删 ConvertDescriptorContractToFixed |
| 包装结构仅一个文件使用 | 冗余层 → 删 | C1 删 DescriptorContractEntry |
| 多参数函数 + 手工拼接顺序 | 隐式协议 → 数据化 | C3 注入段列表（{stage, point, text}） |
| 同一判断散落 N 处（`mode == X` 直比） | 特判 → 辅助函数 | C4 IsCharQuadMode/每线程输出量 |
| 生成端有、消费端零的宏 | 僵尸 → 删 | MTL_DATA_SLOT_COUNT（glsl 零消费） |
| 名字过时（旧架构时代）但功能全活 | 纯命名 → 改名 | BuildVSIndexTableDecls → BuildMeshIndexTableDecls |
| 手写算法有现成标准库 | 替换 | glm packUnorm4x8 取代自研打包 |

要点：
- **改名 ≠ 重构**：先 grep 确认功能活着（有调用者），再改；改名要 grep 手写常量，
  不能只替换命名字面量（kMeshFragment 教训：VK_SHADER_STAGE_ALL_GRAPHICS 漏改）。
- **表化不是万能**：规则逻辑各异、表化仅换分派形式（无真源消除）时不做
  （候选2 弃：CapabilitySubset switch 与 manifest 回退交织）。
- **技术选型先做替代方案分析**：现成库/SPIRV-Reflection/TOML 外移三方向都论证过
  不优于现状（@ulre 注释协议）——维持现状 + 白名单校验才是结论。

## 四、改造技法（六种）

1. **表驱动**：{name, value} 静态表、成员指针表（`{"emit_uv0", &Config::emit_uv0}`）、
   注册表（GetName/Parse/Count）。消灭 if-else 链与平行表。
2. **X-macro**：`#define XXX_LIST \ HGL_ERROR(A) \ HGL_ERROR(B)` + 两次展开
   （枚举定义处 `name,`；名字函数处 `case X::name: return #name;`）。
   错误增删只改列表一处，枚举与名字字符串永不脱节。
3. **数据化列表**：把「拼接顺序」变成「有序段列表」（结构数组），实现按属性归组
   （如 AfterVersion 组合并一次注入，避免多次插入逆序的坑）。
4. **辅助函数收敛**：散落特判统一为命名辅助（IsXxxMode/GetXxxPerInvocation），
   语义名取代散写枚举比较，约定集中一处修改。
5. **结构收敛**：删包装（struct 只包一个 vector）、删往返转换、就地规范化
   （in-out 参数填回规范化值，转换函数消失）。
6. **显式报错**：未知 key 白名单校验（拼写错误显式失败，不静默降级默认）。

## 五、执行纪律

1. **先分析后动手**：用户「仅做分析」时严格遵守；分析后给方案选项让用户拍板
   （A/B/C/D 详述 → 用户选，不替他决定）。
2. **量化前不下结论——数断言主题，不按文件行数推断**（2026-08-30 实测教训）：
   曾据「回归门 5,007 行」断定其为「GLSL 文本断言快照锁、可降到 1,200 行」，
   实测 `GetFinalGLSL()` 全门仅 7 处、`layout(set=` 断言仅 2 行——主体是 hash/契约/
   manifest/缓存身份断言，整条改造前提不成立。**判断"某文件是什么性质"必须 grep 该性质的
   特征标记并计数**，行数只说明体量不说明性质。同理：判断"表是否重复"要 grep 现有表
   （见反模式），判断"函数是否死"要 grep 调用者。
3. **从简到繁验证**：先单 cube/2D，再复杂多对象（Lit PBR、Atmosphere、MultiFont）。
4. **逐处 patch**：perl 批量编辑出过事故，宁可多次 patch 不批量脚本。
5. **回归门双跑**：删 build/cache-hot 后跑两遍，输出 IDENTICAL 才算过；
   错误计数 grep 注意流合并（回归门 FAIL 走 stderr）、VUID 无 ERROR: 前缀。
6. **每步独立提交**：一个行为一个 commit，中文消息说明「改了什么+为什么+
   验证状态」。提交纪律：git status 过滤 submodule 混入。
7. **大任务分步**：C1 拆 T1（扩展铺路，可编译）→ T2（结构切换大改）→ T3（验证），
   每步可独立验证，编译错误定位范围小。
8. **编译错误优先静态定位**：grep/读源码/git 历史对照找根因，不瞎试；
   C++ 端问题用日志追踪，RenderDoc 仅最终视觉确认。
9. **删完必复查**：全仓 grep 零残留（含注释提及、`entry.canonical` 这类访问模式），
   用户会逐文件复查删除彻底性。

## 六、验证清单（每轮改造必过）

1. VS 构建零错误（用户 IDE；bash 无 VS 2022 工具链）
2. 回归门全 PASS（ShaderResourceSchemaRegressionGate.exe all，43 用例）
3. hash/缓存稳定性：删缓存目录后两遍运行 IDENTICAL（证明 key 链路未被破坏）
4. 示例渲染视觉确认（重点：PBR/文字 blend/大气）
5. 技能/文档收尾：技术汇报落 doc/，可复用流程沉淀 skill
