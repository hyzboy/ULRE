# 输入事件系统评估与改进建议

## 现状概览
- 分层分发链：`EventDispatcher` 向子节点广播，可选 `exclusive_dispatcher` 进行短路。
- 事件由 `EventHeader { type, index, id }` + 非类型安全的 `uint64 data` 携带，子类用重解释转换解析。
- 专用处理器（如 `MouseEvent`、`WindowEvent`）继承 `EventDispatcher` 并解包对应 union。
- 子节点存于 `SortedSet<EventDispatcher*>`；父子指针手工维护；独占逻辑改变父指针。

## 主要痛点 / 风险
- 强耦合 `uint64 data` 重解释转换，依赖布局与对齐，缺乏 payload 长度校验。
- 仅对枚举做 `RangeCheck`，`index`、`button` 等未校验，存在越界写风险（如鼠标按钮数组）。
- `exclusive_dispatcher` 会更改父指针和归属，但生命周期/所有权无清晰约定（裸指针，无 RAII）。
- 使用 `SortedSet` 以指针排序，分发顺序不确定，易随地址变化而漂移。
- `EventProcResult` 粗粒度（仅 Continue/Break），缺少“已处理但继续/停止冒泡”的显式语义。
- 无按源/ID 的订阅过滤，所有子节点都会收到匹配源的事件；规模增大时成本高。
- 输入映射层 (`InputMapping.h`) 为空：缺少动作/上下文抽象和设备重映射能力。
- 线程安全未定义，分发树增删缺少同步或单线程契约。

## 低侵入增量改进
1) **类型安全的 payload**：以强类型结构或 `std::variant` 包装 payload，提供统一解码辅助，增加对齐/尺寸断言。
2) **校验与防御**：集中校验 `index`、`id` 和事件子字段（如按钮范围）；未知 ID/源打印调试日志或计数。
3) **分发语义明确化**：扩展 `EventProcResult`（如 `Handled`, `StopPropagation`），区分错误与正常终止；允许“已处理但继续冒泡”策略。
4) **确定性顺序**：以 `std::vector` + 显式优先级/注册顺序替换指针排序的 `SortedSet`。
5) **所有权与生命周期**：文档化父子所有权；考虑 `std::unique_ptr` 管理子节点，父指针用弱引用/观测指针；析构时避免交叉修改父列表。
6) **可观测性**：在分发前后可选插桩/日志，记录耗时与吞吐，便于调试复杂输入链。

## 中期重构选项
1) **事件信封 + 访客模式**：`struct Event { EventHeader header; std::variant<WindowEventData, MouseEventData, KeyboardEventData, JoystickEventData> payload; }`，`OnEvent(const Event&)` 避免不安全转换并可编译期穷举。
2) **基于订阅的路由**：由层级广播转为按源/ID 订阅的路由表，降低无关分发；支持焦点/上下文过滤（UI vs 游戏内）。
3) **输入映射层落地**：实现动作表与设备配置（PS/Xbox/Switch），支持重绑定、组合键/轴、死区与归一化；上下文栈（push/pop）管理焦点。
4) **线程模型**：定义“单线程驱动”或加互斥保护增删；必要时引入无锁队列做跨线程注入。
5) **可测试性**：提供合成事件的测试夹具，验证分发顺序、停止规则、状态（如按键按下表）。

## 长期方向
- 转向“事件总线 + 类型化通道”：发布者推送强类型事件，监听者带过滤订阅；高频输入可选异步队列。
- 分层职责：解码（OS → 规范化输入）、映射（规范输入 → 动作）、路由（动作 → 系统）、焦点管理（独占/栈）独立处理。
- 扩展输入状态学：长按时长、双击识别、轴类死区/曲线、设备标定等能力。

## 建议的下一步
- 先选一条短期目标：(1) 校验+顺序+所有权加固，或 (2) 原型化 typed `Event` 信封。
- 从鼠标/键盘路径试点，配套单元测试与基准评估分发开销。
- 填充 `InputMapping` 的最小可用动作映射，并与现有分发输出对接。
